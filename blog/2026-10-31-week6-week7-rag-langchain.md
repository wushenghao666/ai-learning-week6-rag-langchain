## 项目结构

项目目标是让程序回答自己的学习记录，并显示回答所依据的原文片段。项目包含资料读取、检索、模型调用和本地网页。

第六周完成问答链，第七周完成网页和公网部署。网页提供检索、模型回答和来源片段。后续可以在这条链上增加登录、数据库和 Agent 工具。

## 最小链路

项目现在只有四个动作：

1. 读取 `data/raw/` 下的 Markdown 快照；
2. 按标题切成短段落；
3. 用问题和段落的关键词重合数排序，取前几段；
4. 把问题和段落交给一个 OpenAI 兼容的 Chat Completions API。

这条链和 LangChain 的基本思路相同：loader、splitter、retriever、prompt、model。项目把这些步骤写成几个可以直接阅读的 Python 函数，也保留了与 LangChain 组件对应的接口边界。以后如果想练习 LangChain，只需要把 `retrieve()` 换成 Retriever，把 `answer()` 换成模型调用，网页接口不需要改。

核心调用只有一行：

```python
result = ask("第四周怎样实现会话恢复？", k=4, retrieve_only=True)
```

检索模式可以独立运行；配置 `OPENAI_API_KEY` 后，取消网页上的“只检索”即可调用模型。密钥只留在本地 `.env`，前端不会读取。

## 资料和检索

资料库使用前几周已经写过的博客和 README 快照。程序启动时按 Markdown 标题切分，每段默认不超过 700 个字符，并保存来源文件和章节名。检索只做简单的词集合重合：英文、数字按单词处理，中文按连续双字词处理。资料量只有几篇文章时，这个方法足够快，也更容易调试。

页面会先显示检索结果，再决定是否调用模型。这样可以区分两个问题：是没有找到依据，还是模型没有正确使用依据。没有命中时程序直接返回“没有检索到相关资料”，不会发起模型请求。

## 在线示例

在线问答页：[GitHub Pages](https://wushenghao666.github.io/ai-learning-week6-rag-langchain/)。后端 API 部署在 [Render](https://ai-learning-week6-rag-langchain.onrender.com)，页面通过它完成检索和模型调用。

## 本地页面

启动命令：

```powershell
.\.venv\Scripts\python.exe -m src.web
```

本地运行时打开 http://127.0.0.1:8006/。输入问题后可以调整片段数，或者点击示例问题。默认是只检索模式，适合没有密钥时演示；需要完整回答时，取消勾选后再提交。

页面只保留必要信息：状态、模型回答、来源章节和原文片段。页面展示当前问题、回答和来源片段，资料中的命令作为文本显示。

## 两周后的结果

这次重做后，项目从“完整 RAG 实验平台”变成了一个可以在本机解释清楚的练习：

- 能从本地 Markdown 找到相关片段；
- 能选择只看依据，或调用一个兼容 API 生成回答；
- 能在浏览器里复现同一个问题；
- 没有密钥、网络或模型时，检索部分仍然可用。

原资料和实验报告作为项目记录保留。后续如果继续学习 LangChain，可以按顺序增加 `ChatPromptTemplate`、`RunnableSequence` 或一个真正的 Retriever，每次只替换一层，避免一次引入整套 Agent 架构。

这次的经验是：先让一条短链跑通，再扩展抽象。对学习项目来说，可解释、可重跑比功能数量更重要。
