# 本地页面示例与过程展示补充

日期：2026-10-25。

新增六个可点击示例，分别列出预期结果和预期依据，保留一个旧说明判断的已知失败案例。选择示例仅填入输入框，点击查询才运行，预期结果不会注入模型上下文或替代实际答案。手动编辑问题后，不匹配示例的预期卡片隐藏。

检索方式、片段数及只检索均增加就地说明，包括三种方法的区别、分数的含义、上下文数量的权衡，以及只检索不调用生成 API 的边界。

`POST /api/ask/stream` 用 NDJSON 实时推送可检查的程序事件。关键词分词与排名、问题向量维度与归一化范数、相似度排名、RRF 两路排名与重叠去重、最终片段和编号原文上下文均可展开。生成时展示公开系统指令、实际请求 messages 与模型参数、HTTP 响应状态、最终响应 content、完成原因、Token 用量、模型原文和引用映射。错误保留之前的记录。原 JSON 接口继续可用并附带 trace。

模型采用完整响应，不提供逐 token 内容。界面实时展示程序阶段和等待时间，不生成模型内部思维链。公开响应使用字段白名单，排除供应商 reasoning_content 等推理字段；认证头从不进入事件，返回结果再次排除后端密钥。

## 实际验证

- `reports/tests-whitebox.txt`：34 项测试全部通过，覆盖事件顺序、只检索不调用模型、响应字段过滤、HTTP 错误脱敏、流式错误保留、非法输入及静态资源。成功 API 响应序列使用明确的受控测试响应，未冒充真实平台成功。
- `node --check web/app.js`：通过。
- 浏览器实际选择接口适配示例，预期卡片和问题同时更新；只检索查询实际显示关键词、向量、RRF、上下文、跳过生成及最终片段。
- `whitebox-live.jsonl` 与 `whitebox-first-attempt-summary.json`：真实 HTTP 过程记录。关键词只检索首次事件 70.96 ms 到达，80.04 ms 完成；真实模型请求首次事件 21.40 ms 到达，1111.14 ms 返回 HTTP 429。后者明确标记 model_error，没有生成成功回答。初次实测脚本曾假定真实模型必定 answered 并触发断言，原始记录保留；脚本已修复为分别检查过程协议与实际回答状态。
- 本次没有重跑原 24 题质量评估，原报告和原始响应保持原样。新增功能关注可观察性，旧质量指标不视为这轮新的模型表现。

后续复现可用 `scripts/smoke_whitebox.py --real --name <新名称>`，它会保留实际错误并分别记录 answer_generated。真实模型受账户速率与服务状态影响，HTTP 429 时可以先勾选只检索查看本地过程。
